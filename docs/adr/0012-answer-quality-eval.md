# ADR-0012: 챗봇 답변 품질 정량 평가와 구조 A/B 비교

- 상태: 승인 대기
- 결정자: 주희정
- 관련: [ADR-0009](0009-agent-hybrid-orchestration.md), [ADR-0011](0011-anomaly-eval-metrics.md), [data/eval/README.md](../../data/eval/README.md)

## 배경

[ADR-0009](0009-agent-hybrid-orchestration.md)는 에이전트를 레거시 Supervisor+워커에서 현재의
Planner+병렬 Fetch 구조로 교체하며 **운영 지표**(지연·LLM 호출수·토큰·비용)의 대폭 개선을
실측으로 입증했습니다. 그러나 "빠르고 싼 답이 과연 좋은 답인가"에 해당하는 **답변 품질 축**은
비어 있었습니다. 기존 품질 벤치(`agent_quality_bench.py`)는 규칙이 잘 처리하는 4개 질의만
채점해 두 구조 모두 `pass_rate 1.000`이 나왔고, 이는 절대 품질이 아니라 소규모 회귀 게이트
통과를 뜻했습니다. [ADR-0011](0011-anomaly-eval-metrics.md)에도 "규칙이 처리하는 질의로만
채점해 1.000이 나온 착시"를 적대적 케이스 추가로 바로잡은 이력이 있습니다.

본 ADR은 이 빈칸을 채우기 위해 **적대적·실전 질의를 대량 포함한 평가 셋**과 결정적·추정 지표를
설계·실측하고, 레거시 vs 현재 구조의 답변 품질을 정직하게 비교한 결과를 기록합니다.

## 결정

### 1. 답변 품질 평가 셋을 회귀 게이트와 분리해 신설 (45건)

`data/eval/`에 4개 카테고리 45건을 두고 `tests/golden`(회귀 게이트)과 분리합니다.
규칙이 잘하는 질의로만 채우면 1.000이 재발하므로, 적대적·함정 질의를 33%(15건) 포함합니다.

| 카테고리 | 건수 | 목적 |
| --- | --- | --- |
| 단순 조회 (simple) | 10 | 라우팅·엔티티 정확도 baseline |
| 진단·멀티툴·매뉴얼 결합 (diagnostic) | 12 | 헤드라인 win-rate 주력 |
| 잡담·범위 밖 (chitchat_oob) | 8 | 과잉 도구 호출 방지 |
| 적대적·함정 (adversarial) | 15 | 미존재·폐지코드·오전제·금지조치·인젝션 |

각 케이스는 기대 도구·엔티티·근거 doc_id·이상적 답변 요지와, 적대적 케이스의 환각 금지 문자열·
정직 보고 기대 라벨을 가집니다. 정답 근거는 시드(`scripts/seed_data.py`) 활성 알람 실측과 매뉴얼
원문(`data/rags/sources`)입니다.

### 2. 지표를 결정적/추정으로 분리 표기

정직성을 위해 지표를 성격별로 나눠 보고합니다. 결정적 지표는 재현 시 동일 규칙으로 같은 값이
나오고, 추정 지표는 LLM 판정이라 신뢰구간을 동반합니다.

- 결정적: 라우팅 정확도 · 정답 키워드 포함률 · 인용률 · 환각율(미존재 대상 한정) ·
  정직 보고율 · 검색 hit@k·recall@k·MRR
- 추정(95% 부트스트랩 CI): Pairwise A/B win-rate(헤드라인) · 루브릭 1~5 · Faithfulness

### 3. LLM judge는 생성 모델과 분리한 상위 모델 사용

답변 생성은 gpt-5-mini, 판정은 gpt-5로 분리해 자기선호(self-preference) 편향을 완화합니다.
Pairwise는 blind + 위치 스왑 2회로 위치 편향을 제거하고, 사람 스팟체크 20건으로 judge 신뢰도를
대조 검증합니다.

### 4. 평가 실행 전 데모 데이터 시각을 현재로 재정렬

시드 텔레메트리는 고정 시각(2026-07-08)에 앵커되어, 실행 시점이 그보다 뒤면 에이전트의
"현재 시각 기준 최근 N시간" 조회가 빈 결과가 됩니다. 이 아티팩트가 특정 구조(데이터 범위 인지
프롬프트를 가진 오케스트레이터)에 유리하게 작용하므로, `reanchor_demo_data.py`로 최신 tick을
현재로 평행 이동해 라이브 시뮬레이터가 현재까지 적재한 상태를 재현한 뒤 평가합니다.

## 방법론

- 대상: `agent_orchestrator_enabled` off(레거시 Supervisor+워커) vs on(현재 Planner+병렬 Fetch)
- 통제: 동일 모델(gpt-5-mini)·동일 코퍼스(매뉴얼 3종 157청크)·동일 시드·동일 평가 셋,
  grounding·suggestions off 고정
- 반복: 케이스·설정당 REPS회, 동시 실행 CONCURRENCY (지연은 동시성 영향으로 참고치, 권위
  지연은 ADR-0009)
- 재현 스크립트:
  - `scripts/bench/reanchor_demo_data.py` (데이터 재정렬)
  - `scripts/bench/agent_answer_quality_bench.py` (실행·결정적 지표·원자료 저장)
  - `scripts/bench/agent_pairwise_judge.py` (pairwise·루브릭·faithfulness)
  - `scripts/eval_rag.py --golden-dir data/eval` (검색 hit@k)
  - `scripts/bench/quality_spotcheck_sheet.py` (사람 스팟체크·judge 신뢰도)

## 측정

> 측정일 2026-07-30, gpt-5-mini 생성 / gpt-5 판정, reps=2 (설정당 n=90), n_cases=45, 동시성 6
> 단가 gpt-5-mini 입력 $0.25 / 출력 $2.00 per 1M (2026-07 기준)
> LLM 생성 확률성으로 실행마다 수치가 변동하며, 추정 지표는 95% 부트스트랩 CI를 병기합니다.

### M-1. 헤드라인: Pairwise win-rate · Faithfulness · 검색 hit@k

| 축 | 지표 | 레거시 | 현재 | 판정 |
| --- | --- | --- | --- | --- |
| 품질 | Pairwise 현재 선호 승률 (tie=0.5) | 0.461 | 0.539 | CI [0.411, 0.672]가 0.5를 포함, 통계적 동등 |
| 근거 | Faithfulness 1~5 | 1.82 | 2.18 | 둘 다 낮음, 현재가 근소 우위 |
| 검색 | hit@3 / MRR | 0.909 / 0.591 | 0.909 / 0.591 | RAG 스토어 품질, 구조 무관 공통 baseline |

Pairwise는 45건 blind + 위치 스왑 2회, 현재 22승·레거시 19승·4무, 위치 일관성 0.822입니다.
승률 95% CI가 0.5를 포함하므로 **두 구조의 답변 품질은 통계적으로 동등**하며, 현재 구조는
품질 저하 없이 아래 운영 지표(호출·토큰·비용)를 절반 이하로 낮춘 것이 핵심 결론입니다.

Faithfulness는 두 구조 모두 5점 만점에 2점 안팎으로 낮고 미지지 주장이 평균 7~8개입니다.
이는 매뉴얼 청크 밖의 현장 조치 조언까지 엄격히 미지지로 세는 보수적 심사 특성이 섞인
결과지만, 구조와 무관하게 **근거 충실성 자체가 시스템 공통 약점**임을 시사합니다.

### M-2. 결정적 품질 지표 (설정별 종합, n=90)

| 지표 | 레거시 | 현재 | 해석 |
| --- | --- | --- | --- |
| 라우팅 정확도 | 0.878 | 0.944 | 현재 우위 |
| 정답 키워드 포함률 | 0.911 | 0.867 | 레거시 우위 (단순 조회 영향, M-4) |
| 인용률 | 0.545 | 0.955 | 현재 대폭 우위 |
| 정직 보고율 | 0.900 | 0.900 | 동일 |
| 환각율 (미존재 대상) | 0.50 | 0.00 | 표본 얇음(케이스 1×2회), 하한 신호 |
| 에러율 | 0.000 | 0.000 | 동일 |

환각율은 `must_not_contain` 라벨을 가진 미존재 설비 케이스(EVAL-D01) 한정이라 분모가 얇습니다.
레거시는 미존재 설비를 정직 보고하면서도 무관한 실제 설비(EQP-A05·ERR-402) 데이터를 자발적으로
끌어와 감점됐습니다(순수 창작보다 범위 이탈에 가까움). 견고한 환각 신호는 M-1 Faithfulness입니다.

### M-3. 루브릭 1~5 (추정)

| 항목 | 레거시 | 현재 |
| --- | --- | --- |
| 정확성 | 2.91 | 3.09 |
| 근거 | 2.40 | 2.56 |
| 완결성 | 3.53 | 3.58 |
| 간결성 | 3.44 | 3.84 |

네 항목 모두 현재가 근소 우위이며, 간결성 격차가 가장 큽니다(병렬 Fetch·단일 Planner의 군더더기 억제).

### M-4. 카테고리별 (라우팅 / 키워드 / 정직 / 환각)

| 카테고리 | n | 레거시 라우팅 | 현재 라우팅 | 레거시 키워드 | 현재 키워드 |
| --- | --- | --- | --- | --- | --- |
| simple | 20 | 1.000 | 1.000 | 0.950 | 0.700 |
| diagnostic | 24 | 0.708 | 0.958 | 0.833 | 1.000 |
| chitchat_oob | 16 | 1.000 | 1.000 | 0.938 | 0.938 |
| adversarial | 30 | 0.867 | 0.867 | 0.933 | 0.833 |

가장 중요한 트레이드오프입니다. 현재 구조는 **진단(diagnostic)에서 라우팅·키워드 모두 우위**
(0.71→0.96, 0.83→1.00)지만, **단순 조회(simple) 키워드에서 열위**(0.95→0.70)입니다. 원인은
현재 Planner가 활성 알람 확인에 `get_alarm_history`(최근 1시간·raised_at 필터)만 호출해, 발생
시각이 창 밖인 지속 알람을 놓치는 경우가 있기 때문입니다. 레거시는 `get_sensor_logs`까지
호출(질의당 6회)해 최신 tick의 alarm_code로 잡아냅니다. 적대적 정직 보고율은 둘 다 0.90으로 동일합니다.

### M-5. 운영 지표 (본 실행 참고치 + ADR-0009 권위치)

| 지표 | 레거시 | 현재 | 출처 |
| --- | --- | --- | --- |
| p50 지연 | 55.22s | 16.77s | ADR-0009 (권위, 스텁 통제) |
| LLM 호출/질의 | 8.3 | 2.8 | ADR-0009 |
| 입력 토큰/질의 | 16,502 | 3,743 | ADR-0009 |
| 본 실행 LLM 호출/질의 | 6.0 | 3.0 | 본 실행 |
| 본 실행 입력 토큰/질의 | 36,306 | 9,162 | 본 실행 (실 MCP 관찰값이라 스텁보다 큼) |
| 본 실행 비용/질의 | $0.01454 | $0.00552 | 본 실행 (현재 -62.0%) |
| 본 실행 p50 지연 | 31.2s | 26.4s | 본 실행 (동시성 6 영향, 참고) |

본 실행은 실제 MCP 관찰값(센서 로그·매뉴얼 청크)을 재주입하므로 입력 토큰이 스텁 기반
ADR-0009보다 큽니다. 절대치가 아니라 **구조 간 비(현재가 호출 2배·토큰 4배·비용 2.6배 절감)**를
읽어야 하며, 권위 지연·토큰은 통제 실험인 ADR-0009를 따릅니다.

### M-6. judge 신뢰도 (사람 스팟체크 20건)

`quality_spotcheck_sheet.py generate`로 카테고리 층화 20건 블라인드 시트(`spotcheck_sheet.csv`)를
생성했습니다. 사람이 `human_pick`(1·2·tie)을 기입한 뒤 `score` 서브커맨드로 사람-judge 완전
일치율과 사람 기준 현재 선호 승률을 산출해 judge 신뢰도를 검증합니다. 사람 채점은 자동화 대상이
아니므로 본 ADR 작성 시점에는 미기입 상태이며, 채점 후 수치를 본 절에 채웁니다.

## 결론

- 답변 품질은 두 구조가 **통계적으로 동등**합니다(Pairwise CI가 0.5 포함, 루브릭 근소차). 따라서
  ADR-0009의 오케스트레이터 전환은 품질 저하 없이 호출·토큰·비용을 절반 이하로 낮춘 결정으로
  재확인됩니다.
- 현재 구조는 **인용률·라우팅·간결성·환각 억제에서 우위**, 레거시는 **단순 활성 알람 조회의
  키워드 포착에서 우위**라는 트레이드오프가 드러났습니다. 후자는 Planner의 알람 조회 도구 선택
  개선(지속 알람은 `get_sensor_logs` 병행)으로 좁힐 수 있는 후속 과제입니다.
- 두 구조 공통으로 **근거 충실성(Faithfulness ~2/5)**이 약합니다. 검색 hit@3=0.909로 문서는 잘
  회수되나 답변이 근거를 벗어난 조언을 덧붙이는 경향이라, 근거 결속 강화(grounding·인용 강제)가
  구조와 무관한 다음 개선 축입니다.
- "품질 1.000 착시"는 적대적 33% 포함으로 해소됐습니다. 실측 라우팅·키워드·인용·환각·win-rate가
  모두 1.0 미만의 변별 있는 값으로 나와 구조 비교가 가능해졌습니다.

## 폐기안 (Rejected alternatives)

- 기존 4케이스 pass_rate 유지: 1.000 착시로 구조 차이를 드러내지 못해 폐기
- 단일 모델 self-judge(gpt-5-mini 생성·판정 동일): 자기선호 편향 위험으로 상위 분리 모델 채택
- 결정적 키워드/규칙 채점만으로 품질 결론: 오전제 정정·환각을 문자열로 판별하기 어려워 LLM
  pairwise·faithfulness를 헤드라인으로, 결정적 지표는 하한 근거로 병기

## 한계

- 추정 지표는 judge 모델 편향·표본 크기(45건)의 한계가 있어 CI와 사람 스팟체크로 보완합니다.
- 결정적 환각율은 미존재 대상 케이스에 한정한 보수적 하한이며, 오전제 정정형 환각은 LLM
  faithfulness가 담당합니다.
- 본 실행 지연은 동시 실행 영향을 받으므로 권위 지연·토큰은 ADR-0009(스텁 통제)를 따릅니다.
- LLM 생성 확률성으로 실행마다 수치가 변동하므로 reps·CI로 분산을 표기합니다.
