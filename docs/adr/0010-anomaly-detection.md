# ADR-0010: 자기지도 이상 감지 레이어 도입 (PCAX + EWMA, 섀도우 우선 배포)

- 상태: 승인 (2026-07-20), 실발령은 섀도우 관찰 후 전환 예정
- 결정자: 주희정
- 관련: [ADR-0001](0001-architecture.md), [ADR-0004](0004-realtime-sse.md), [ADR-0005](0005-simulator-spc.md), [docs/experiments/decisions.md](../experiments/decisions.md), [docs/anomaly-serving.md](../anomaly-serving.md), feature/168-anomaly-experiment-base(#169), feature/170-anomaly-eval-v2-ts2vec(#171), feature/172-anomaly-realtime-tuning(#173), feature/174-anomaly-serving(#175), feature/176-anomaly-shadow-mode(#177), feature/179-anomaly-transition-suppress(#180), feature/181-anomaly-drift-refit(#182), feature/183-anomaly-per-equipment-calib(#186)

## 배경

기존 이상 감지는 시뮬레이터가 부여하는 고정 임계·알람 코드와 LLM 판단에 의존했습니다
([ADR-0004](0004-realtime-sse.md) 작성 시점에 주기 감지 잡은 미구현 상태였습니다). 이 방식은
두 가지를 놓칩니다. 첫째, 설비마다 정상 운전점이 달라 공통 임계로는 개체 차를 반영할 수
없습니다. 둘째, 각 센서가 모두 임계 안쪽에 있으면서 센서 간 관계만 깨지는 복합 이상은
원리적으로 감지되지 않습니다.

본 ADR은 정상 데이터만으로 학습하는 이상 감지 레이어를 도입한 결정과 그 실측 근거를
기록합니다. 실험 단위의 상세 기록은 [docs/experiments/](../experiments/)에 EXP-000~008과
[decisions.md](../experiments/decisions.md)로 남아 있으며, 본 ADR은 그중 시스템 수준 결정
(감지 구조·모델 선택·서빙 배치·배포 절차)만 추려 근거와 함께 정리합니다.

## 결정

### 1. 임계를 대체하지 않고 레이어로 얹습니다

규칙 임계를 제거하고 학습 모델로 대체하는 대신, 규칙 레이어를 그대로 두고 그 위에 통계
레이어를 추가합니다. 대체 대상은 임계가 아니라 **LLM의 판정 역할**이며, LLM은 설명 역할로
이동합니다.

근거는 역할이 다르기 때문입니다. 과온·과압 같은 안전 한계는 결정론적이고 감사 가능해야 하며,
급성 이상은 포인트 단위로 즉시 잡혀야 합니다. 통계 레이어는 윈도우를 채워야 판정하므로 급성
지연이 규칙보다 깁니다(EXP-002에서 급성 평균 지연 +5.6 tick). 반대로 규칙은 임계 안쪽 이상을
구조적으로 못 잡습니다. 두 레이어의 실측 사각이 서로 반대라는 점이 레이어드의 근거입니다.

| 이상 유형 | 규칙 레이어 recall | 통계 레이어 recall |
| --- | --- | --- |
| 급성 (acute) | 1.0 | 1.0 |
| 상관 붕괴 (corr_break) | 0.0 | 1.0 |
| 진동 (oscillation) | 1.0 | 1.0 |
| 분산 증가 (variance) | 1.0 | 1.0 |
| 임계 안쪽 드리프트 (drift_inband) | 0.5 | 0.0 |

평가 세트 v2 기준입니다. 규칙은 `exp_004_rule`(감지 유예 60 tick), 통계는 최종 구성
`exp_008_suppress`(유예 180 tick)이며 유예가 달라 recall을 직접 비교할 때는 주의가 필요합니다.
다만 `corr_break`는 규칙이 유예와 무관하게 원리적으로 감지 불가한 구간입니다.

부수 효과로 장애 시 폴백이 확보됩니다. 통계 레이어가 죽어도 규칙 레이어 단독으로 동작이
계속됩니다.

### 2. v0 모델은 PCA MSPC(PCAX), TS2Vec은 보류합니다

최초 구상은 임베딩 + cosine 유사도였으나, 평가 체계가 없는 상태에서 encoder부터 넣으면 개선
여부를 판정할 수 없다는 이유로 재구성 기반(PCA MSPC의 T²+SPE)을 먼저 세웠습니다. 채널별 기여도를
수식으로 직접 산출할 수 있어 LLM 설명 근거로 쓰기 좋고, 학습이 초 단위라 반복 실험에 적합합니다.

v1 후보였던 TS2Vec은 EXP-005에서 **보류로 판정**했습니다. 판정 기준이었던 `corr_break`에서
표현에 신호 자체가 없었고(이상 전후 점수 중앙값 0.73으로 동일), 오탐 소폭 우위·지연 소폭 열위로
교체 비용을 정당화하지 못했습니다.

| 지표 | v0 (PCAX) | v1 후보 (TS2Vec+kNN) |
| --- | --- | --- |
| event_recall | 0.773 | 0.773 |
| 오탐/설비·일 | 4.74 | 3.70 |
| 감지 지연 평균 (tick) | 12.41 | 15.24 |
| corr_break 감지 | 불가 | 불가 (신호 부재) |

다만 EXP-005는 D3(baseline 표현)을 확인하는 소득이 있었습니다. 동일 encoder에서 kNN 은행이
단일 centroid cosine보다 진동 recall 0.50 대 0.00으로 우세해, 정상 운전이 다중 모드라는 전제가
확인되었습니다. 이 결과는 실측 데이터 확보 후 v1 재검토 시의 출발점으로 남깁니다.

### 3. 모델은 하나, 점수 소비 경로는 둘로 나눕니다

`corr_break`를 잡기 위해 표현을 교체하는 대신, **같은 PCAX 점수를 두 방식으로 소비**합니다.
윈도우당 신호가 약 3σ로 이미 존재하는데 단발 임계를 못 넘는 것이 병목이었으므로, 점수
시계열을 누적하면 표현 교체 없이 해결된다는 판단이었습니다.

- raw 경로: 급성·드리프트 감지, 저오탐
- EWMA 경로(α=0.1, 클리핑 3.0): 지속 저강도 이상 감지

EXP-006에서 이 판단이 맞았음이 확인되었습니다. EWMA 도입으로 `corr_break` 지속 감지를
달성했습니다(EXP-007 최종 구성 기준 recall 1.0, 평균 지연 104 tick).

클리핑은 실험 중 발견한 부작용 대응입니다. 클리핑 없이 EWMA만 적용하면 점화 구간의 거대 점수가
감쇠 꼬리를 만들어 오탐이 293건까지 늘었고, winsorize로 134건까지 줄였습니다.

### 4. 서빙 파라미터는 윈도우 60초 / stride 30초 / 지속 확인 K=2입니다

EXP-003은 "지연은 windowing 튜닝과 무관"이라고 결론지었으나, EXP-007에서 이를 **v1 평가 세트
한정으로 정정**했습니다. v2 스윕에서는 실시간성을 stride가 지배하고(급성 지연 = stride, 윈도우
무관), 윈도우는 진동 감지 품질을 지배했습니다(60초 최적). 이에 따라 초기값 120초/60초를
60초/30초로 재확정했습니다.

지속 확인 K 규칙은 EXP-006에서 "오탐을 상쇄할 레버"로 기대했으나, EXP-007에서 **완만한 레버에
그친다고 정정**했습니다(raw 15.4 → 11.7, EWMA 18.8 → 17.5). 잔여 오탐이 고립 스파이크가 아니라
점화 모드 전이라는 지속형이라 K로 죽지 않았기 때문입니다.

### 5. 모드 전이 오탐은 레시피 신호 없이 억제합니다

EXP-006·007이 지목한 최대 오탐원은 점화·램프업 같은 정상 모드 전이였고, 정석 해법은 레시피
상태 신호로 마스킹하는 것이었습니다. 그러나 현재 시뮬레이터·실설비 연동에 레시피 컨텍스트가
없으므로, **raw 점수 크기 자체로 전이를 식별**하는 방식을 택했습니다.

전이 구간의 raw 점수(점화 시 5000 이상)가 진짜 이상(최대 169)과 완전히 분리되어 임계
1000으로 격리 가능했습니다. 전이 구간과 이후 정착 구간(10 윈도우)을 발령에서 제외합니다.

| 지표 | 억제 전 (exp_008_base) | 억제 후 (exp_008_suppress) |
| --- | --- | --- |
| 오탐/설비·일 | 17.48 | 3.70 (-78.8%) |
| event_recall | 0.909 | 0.909 (유지) |
| auc_pr | 0.983 | 0.995 |

급성은 규칙 레이어가 담당하므로 통계 레이어가 전이 구간을 무시해도 안전합니다. 레이어드 구조
(결정 1)가 이 억제를 가능하게 한 전제입니다.

### 6. 모델은 공정 유형 단위, 임계는 설비 단위로 둡니다

설비별 표본이 적합에 충분하지 않아 모델은 공정 유형(`process_type`)을 키로 적합합니다. 대신
개체 차(챔버 차·센서 오프셋)는 각 설비 자신의 정상 분포로 산출한 EWMA 한계로 흡수합니다
(`equipment_anomaly_calibrations`). 캘리브레이션이 없는 설비는 공정 유형 한계로 폴백합니다.

아티팩트 배치는 갱신 주기를 기준으로 나눴습니다. 스코어링 코드는 이미지, 설비별 baseline·임계는
RDS입니다. baseline은 정비 이벤트와 드리프트 정책에 따라 런타임에 갱신되는 데이터이므로
이미지에 구우면 갱신 정책 자체가 성립하지 않습니다. 파라미터는 pickle이 아니라 JSONB 배열로
직렬화해 라이브러리 버전 변화에 견고하게 했습니다.

캘리브레이션 도입 과정에서 기존 한계 산출의 오염 두 건을 발견해 함께 수정했습니다.

| 오염 | 증상 | 수정 |
| --- | --- | --- |
| EWMA 워밍업 미제외 | 첫 윈도우 점수가 높은 설비는 감쇠 구간이 상위 표본을 독점, 한계 최대 4.4배 팽창 | 워밍업(시정수 5배) 제외 후 분위수 |
| 설비 경계 전이 | 이어붙인 시퀀스에 EWMA를 통째로 적용해 경계마다 전이 발생, 공정 한계 34% 팽창 | 파트별 EWMA 후 결합 |

수정 결과 공정 한계가 0.728에서 0.544로 낮아져 의도한 q0.999 민감도를 회복했고, 설비별 한계는
공정 대비 0.94~1.07배로 수렴했습니다. 동일 프로파일 설비에서는 이 수렴이 정상이며, 실측
데이터에서 개체 차가 있으면 그만큼 벌어집니다.

### 7. 실발령 전에 섀도우 모드로 관찰합니다

기본값을 `anomaly_detection_enabled=false`, `anomaly_shadow_mode=true`로 두고 2단계로
배포합니다. 섀도우 단계에서는 스코어러가 실데이터에 동작하되 WRN-901을 알림 파이프라인에
쏘지 않고 `equipment_anomaly_shadow_events` 저널에만 기록합니다.

근거는 모든 실험이 **합성 데이터 기준**이라는 점입니다. 전이 억제 임계 1000은 합성 램프에서
얻은 값이라 실측 램프에서는 raw 점수가 낮을 수 있고, 캘리브레이션 수정으로 한계가 낮아진 만큼
알람이 늘 수 있습니다. 운영자에게 노출하기 전에 규칙 레이어와 비교 관찰할 구간이 필요합니다.

`anomaly-shadow-report`가 감지를 detector-only(규칙이 놓친 후보)·overlapping·rule-only로
분류하며, 이 라벨이 실발령 전환과 파라미터 조정, 이후 반지도 전환의 근거가 됩니다.

### 8. baseline은 주기 재적합으로 드리프트를 추종합니다

설비 마모로 정상이 서서히 이동하고 정비 후 리셋되므로 고정 모델은 시간이 지나며 오탐이
늘어납니다. 재적합 워처가 staleness 초과 모델을 최근 정상 데이터로 재적합합니다.

이때 서서히 진행되는 고장을 정상으로 학습하는 boiling-frog 위험이 생기므로 방지 장치를 네 겹으로
두었습니다.

| 장치 | 효과 |
| --- | --- |
| 정상 한정 (`alarm_code IS NULL`) | 알람 구간 제외 |
| 최근성 경계 (`recency_days`) | 오래된 정상 age-out |
| 정비 인지 (`repaired_at` 이전 제외) | 정비 전 열화가 정비 후 모델을 오염시키는 것 차단 |
| 표본 가드 (`MIN_TRAIN_WINDOWS`) | 데이터 부족 시 기존 모델 유지 |

## 측정

평가 세트는 시뮬레이터 시나리오로 생성해 git에 얼렸고(v1 15세그먼트·이벤트 16건,
v2 이벤트 22건), 학습 세트는 seed와 설비 ID 접두(TRN-/EVL-)로 이중 격리해 정보 누출을
차단했습니다. 지표 정의는 `anomaly.evaluation.summarize` 단일 소스를 따릅니다.

### 전체 진행 (오탐 기준)

오탐은 감지 유예 설정과 무관하므로 실험 간 직접 비교가 가능합니다.

| 단계 | 구성 | 평가 세트 | 오탐/설비·일 |
| --- | --- | --- | --- |
| EXP-001 | 규칙 베이스라인 | v1 | 72.80 |
| EXP-002 | PCA MSPC 초기 | v1 | 5.87 |
| EXP-003 | v0 config 확정 (w24 s12 q0.999) | v1 | 0.53 |
| EXP-004 | 규칙 베이스라인 | v2 | 116.74 |
| EXP-004 | v0 (PCAX) | v2 | 4.74 |
| EXP-006 | EWMA 경로 추가 | v2 | 19.85 |
| EXP-007 | 실시간 파라미터 + K2 | v2 | 17.48 |
| EXP-008 | 전이 억제 적용 (최종) | v2 | 3.70 |

최종 구성은 v2 기준 규칙 베이스라인 대비 오탐을 **116.74에서 3.70으로 96.8% 감축**했습니다.
EWMA 도입 시 오탐이 4.74에서 19.85로 늘어난 것은 `corr_break` 감지를 얻기 위해 감수한 비용이며,
EXP-008의 전이 억제로 다시 3.70까지 회수했습니다.

### 최종 구성 지표

`exp_008_suppress` 기준입니다(평가 세트 v2, 윈도우 12 tick·stride 6 tick·q0.999·EWMA α=0.1·
클리핑 3.0·K=2·전이 임계 1000·정착 10, 감지 유예 180 tick).

| 지표 | 값 |
| --- | --- |
| event_recall | 0.909 (20/22) |
| 오탐/설비·일 | 3.70 |
| 감지 지연 평균 | 24.2 tick |
| 감지 지연 p90 | 35.6 tick |
| auc_pr | 0.995 |

유형별 recall과 평균 지연입니다.

| 이상 유형 | recall | 평균 지연 (tick) |
| --- | --- | --- |
| acute | 1.0 | 11.0 |
| corr_break | 1.0 | 104.0 |
| drift | 1.0 | 16.25 |
| oscillation | 1.0 | 26.0 |
| variance | 1.0 | 17.0 |
| drift_inband | 0.0 | 미감지 |

### 평가 방법에서 발견한 함정

측정 자체의 결함을 두 건 발견해 평가기를 고쳤으며, 기록으로 남깁니다.

첫째, EXP-001의 규칙 recall 1.0은 실력이 아니라 **구성상 당연한 결과**였습니다. 평가 세트 v1의
이상이 전부 규칙이 잡는 공간에 있었기 때문입니다. 이를 확인하고 규칙이 원리적으로 못 잡는
임계 안쪽 시나리오를 v2에 추가했습니다.

둘째, 장구간 이벤트에서 **배경 오탐이 우연히 이벤트 구간에 적중해 recall이 포화**하는 함정을
EXP-004에서 발견했습니다. 규칙 recall이 1.0으로 잘못 측정되고 있었습니다. 감지 유예
(`max_delay_ticks`)와 유형별 recall 분해를 평가기에 도입해 차단했습니다.

또한 이벤트 구간이 세그먼트의 83%를 차지해 포인트 양성 비율이 78%이므로, `auc_pr`의 절대값
해석은 금지하고 모델 간 상대 비교로만 사용합니다.

## 대안 검토

| 대안 | 폐기 사유 |
| --- | --- |
| 임계 제거 후 통계 레이어 단독 | 안전 한계의 감사 가능성 소실, 급성 감지가 윈도우 길이만큼 지연, 장애 시 폴백 없음 |
| 임베딩 거리 직행 (최초 구상) | 평가 체계 부재 상태에서 개선 판정 불가, 구현 공수 3주 이상 |
| 딥 AE 재구성 | GPU 학습 필요, 일정 대비 과도 |
| TS2Vec 표현 교체로 corr_break 해결 | 표현에 신호 부재 (이상 전후 점수 중앙값 0.73 동일), 교체 비용 정당화 실패 |
| 채널 쌍 상관 피처 추가로 corr_break 해결 | 지연 개선 없음 (131/143 → 131/119), 단발 임계 구조 한계는 그대로 |
| 지속 K 규칙으로 모드 전이 오탐 억제 | 잔여 오탐이 지속형이라 K로 미감소 (17.5 → 17.5 수준), 전이 억제로 대체 |
| 레시피 상태 신호로 마스킹 | 정석이나 현재 레시피 컨텍스트 미연동, raw 점수 분리도로 대체 가능 |
| 설비 단위 모델 적합 | 설비별 표본 부족, 공정 유형 모델 + 설비별 임계 캘리브로 분리 |
| 모델 파라미터를 이미지에 포함 | 재학습 주기와 릴리스 주기가 달라 drift 갱신 정책이 성립하지 않음 |
| pickle 직렬화 | 라이브러리 버전 변화 시 역직렬화 파손 |
| 검증 없이 바로 실발령 | 전 실험이 합성 데이터 기준, 실측 분포 차이를 관찰할 구간 필요 |

## 결과 / 미해결

- 규칙이 원리적으로 못 잡던 상관 붕괴를 recall 1.0으로 감지하면서, 오탐은 규칙 베이스라인 대비
  96.8% 낮습니다(116.74 → 3.70건/설비·일). 규칙 레이어는 그대로 유지되어 급성 감지 속도와
  감사 가능성은 손실되지 않았습니다.
- 남은 리스크로 기록합니다.
  - **임계 안쪽 완만 드리프트(drift_inband)는 두 레이어 모두 못 잡습니다**(규칙 0.5, 통계 0.0).
    통계 레이어는 419~695 tick에 감지하나 유예 180 tick을 넘겨 미감지로 집계됩니다. 현재
    구성으로 커버되지 않는 사각이며, 별도 레버(장기 추세 전용 경로 등)가 필요합니다.
  - 전 실험이 **합성 데이터 기준**입니다. 전이 억제 임계 1000, 캘리브레이션 클램프 범위,
    EWMA 한계는 모두 실측에서 재조정될 수 있습니다. 섀도우 관찰이 그 근거를 수집하는 단계입니다.
  - EXP-003의 v0 config 선정 시 오탐이 절대 2건이라 추정 분산이 큽니다. q0.999는 학습 약 2,900
    윈도우의 극단 분위수라 한계 추정이 불안정하며, 선택 노이즈 위험이 남아 있습니다.
  - 실발령(WRN-901) 전환 시점은 정하지 않았습니다. 섀도우 리포트의 detector-only 라벨을
    운영자가 리뷰한 결과에 달려 있습니다.
  - 재적합 워처는 기본 비활성(`anomaly_refit_enabled=false`)이며, boiling-frog 방지 장치 네 겹은
    설계상 근거만 있고 실측 검증은 되지 않았습니다.
  - v1(TS2Vec) 재검토는 실측 데이터 확보 이후로 미뤘습니다. 판단 기준은 긴 문맥 표현이 요약
    통계가 버리는 형상·순서·채널 간 지연·다중 모드를 실제로 살리는지 여부입니다.
