# 센서 데이터 시뮬레이터 (BE_SIM01_GEN01)

이 문서는 설비 센서 데이터를 모사해 적재하는 시뮬레이터의 역할과 동작을 설명합니다.

## 왜 필요한가

본 시스템은 제조 설비의 실시간 센서 데이터를 분석해 이상을 진단합니다. 그러나 실제 설비
연동은 과제 범위 밖이며, 요구사항은 제공된 샘플 스키마를 기반으로 데이터를 모사하도록
규정합니다(§11). 시뮬레이터는 실제 장비를 대신하여 온도·압력 등 센서값을 주기적으로
생성하고 `equipment_telemetry` 테이블에 적재하는 역할을 담당합니다. 이 데이터가 있어야
MCP 실시간 조회 도구와 에이전트가 진단할 대상이 생깁니다.

## 전체 흐름에서의 위치

```
[시뮬레이터]  →  equipment_telemetry 적재
                     ↓
[MCP 실시간 도구]  →  DB 조회
                     ↓
[AI 에이전트]  →  이상 진단·조치 안내
```

시뮬레이터는 파이프라인의 최상류에서 데이터를 공급합니다. 특히 이상 시나리오 모드는
데모·발표 시 이상 상황을 의도적으로 재현하여 에이전트의 진단 과정을 시연하는 데 사용합니다.

## 구조

생성 로직과 입출력을 분리하여, 순수 계산 부분을 DB·시간 없이 결정론적으로 테스트할 수 있게
구성했습니다.

| 파일 | 담당 역할 |
| --- | --- |
| `src/simulator/profiles.py` | 공정 유형별 센서 정상 범위 baseline 정의 |
| `src/simulator/generator.py` | 센서값 1건 생성 순수 로직 (정상·이상) |
| `src/simulator/main.py` | 주기 적재 루프, CLI 인자, DB 재시도, 시드 대기 |
| `tests/unit/test_simulator.py` | 생성 로직 단위 테스트 |

## 시나리오 모드

### normal

각 설비가 공정 유형 baseline 주변에서 가우시안 노이즈를 갖는 정상값을 생성합니다.
알람은 발생하지 않으며, 상시 배경 데이터 공급에 사용합니다.

공정 유형별 baseline은 다음과 같습니다.

| 공정 유형 | 온도(°C) | 압력 | RF 파워(kW) | 가스 유량(sccm) |
| --- | --- | --- | --- | --- |
| Etching | 42.0 | 1.20 | 2.00 | 150.0 |
| Deposition | 38.0 | 1.10 | 1.50 | 120.0 |
| (기타) | 40.0 | 1.15 | 1.80 | 140.0 |

### err402_temp_rise

지정한 대상 설비(`--target`, 기본 EQP-003)에 냉각 고장 상황을 재현합니다. 서비스
시나리오(§3.2)의 ERR-402 상황과 대응됩니다.

- 온도는 baseline에서 고온 평형점(65°C)으로 **지수 점근**하며 상승합니다.
- 압력은 저압 평형점(0.85)으로 점근하며 저하됩니다.
- 온도가 기준(50°C)을 넘으면 `ERR-402` 알람을 부여합니다.
- RF 파워·가스 유량은 냉각 계통 이상과 무관하므로 정상 범위를 유지합니다.

온도 곡선은 실제 장비처럼 **무한히 상승하지 않고 평형점 부근에서 정착**합니다. 냉각 고장 시
발열과 줄어든 냉각이 새로운 평형점에서 만나는 1차 지연 응답을 모사한 것입니다.

```
step  온도    압력
 0   42.28   1.22   ← 정상 baseline
 1   52.60   1.05   ← 급상승, ERR-402 발생
 2   58.29   0.93
 3   61.69   0.91
 4   63.14   0.87
 ...
10   65.69   0.85   ← 65°C 평형점 부근 정착
```

이상의 강도·속도는 `generator.py` 상단 상수(`ANOMALY_TEMP_PLATEAU`,
`ANOMALY_TIME_CONSTANT` 등)로 조절합니다.

## 실행 방법

### CLI 직접 실행

```bash
uv run simulator                                   # normal, 5초 주기, 무한
uv run simulator --interval 10                     # 10초 주기
uv run simulator --scenario err402_temp_rise --iterations 5 --target EQP-003
```

| 인자 | 기본값 | 설명 |
| --- | --- | --- |
| `--scenario` | normal | normal 또는 err402_temp_rise |
| `--interval` | 5.0 | 생성 주기(초) |
| `--iterations` | 무한 | 반복 횟수, 미지정 시 무한 |
| `--target` | EQP-003 | 이상 시나리오 대상 설비 |

이상 시나리오는 온도가 계속 상승하는 특성상 `--iterations`로 유한하게 실행하는 것을
권장합니다. 골든 E2E 테스트도 이 유한 모드로 시나리오를 결정론적으로 주입합니다.

### docker-compose

`simulator` 서비스로 등록되어 있어 스택과 함께 자동 실행됩니다.

```bash
docker compose up -d          # db·api·mcp와 함께 시뮬레이터도 기동
```

시뮬레이터가 시드보다 먼저 기동되어도 종료되지 않고, `equipment_master`가 채워질 때까지
대기한 뒤 적재를 시작합니다. 따라서 기동 순서와 무관하게 동작합니다.

## 동작 특성

- 한 주기(tick)마다 설비 수만큼 행을 적재합니다(설비 3대이면 tick당 3건).
- DB 연결·적재 실패 시 1회 재시도하고, 실패가 지속되면 해당 주기만 건너뛴 뒤 계속 진행합니다.
- 이상 시나리오 진행 단계(step)는 대상 설비별로 누적되어 온도 상승 곡선을 만듭니다.

## 데이터 규모 참고

기본값(5초 주기, 설비 3대) 기준 하루 약 5.2만 건(약 10 MB)이 적재됩니다. 현재 규모에서는
부하·용량 모두 무시할 수준이나, 장기간 상시 운영 시에는 `--interval` 조정 또는 오래된 로그
정리(retention)를 고려할 수 있습니다.
