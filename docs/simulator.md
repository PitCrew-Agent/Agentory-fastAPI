# 센서 데이터 시뮬레이터 (BE_SIM01_GEN01)

이 문서는 설비 센서 데이터를 모사해 적재하는 시뮬레이터의 역할과 동작을 설명합니다.

## 왜 필요한가

본 시스템은 제조 설비의 실시간 센서 데이터를 분석해 이상을 진단합니다. 그러나 실제 설비
연동은 과제 범위 밖이며, 요구사항은 제공된 샘플 스키마를 기반으로 데이터를 모사하도록
규정합니다(§11). 시뮬레이터는 실제 장비를 대신하여 온도·압력 등 센서값을 주기적으로
생성하고 `equipment_telemetries` 테이블에 적재하는 역할을 담당합니다. 이 데이터가 있어야
MCP 실시간 조회 도구와 에이전트가 진단할 대상이 생깁니다.

## 전체 흐름에서의 위치

```
[시뮬레이터]  →  equipment_telemetries 적재
                     ↓
[MCP 실시간 도구]  →  DB 조회
                     ↓
[AI 에이전트]  →  이상 진단·조치 안내
```

시뮬레이터는 파이프라인의 최상류에서 데이터를 공급합니다. 특히 이상 시나리오 모드는
데모·발표 시 이상 상황을 의도적으로 재현하여 에이전트의 진단 과정을 시연하는 데 사용합니다.

## 구조

생성 로직과 입출력을 분리하여, 순수 계산 부분을 DB·시간 없이 결정론적으로 테스트할 수 있게
구성했습니다.

| 파일 | 담당 역할 |
| --- | --- |
| `src/simulator/profiles.py` | 공정 유형별 센서 정상 범위 baseline 정의 |
| `src/simulator/generator.py` | 센서값 1건 생성 순수 로직 (정상·이상) |
| `src/simulator/main.py` | 주기 적재 루프, CLI 인자, DB 재시도, 시드 대기 |
| `tests/unit/test_simulator.py` | 생성 로직 단위 테스트 |

## 시나리오 모드

시뮬레이터는 SPC 동적 밴드 모델로 센서값을 생성합니다(구현 참고서 §2·§3). 각 변수는
중심선(mu0 + 드리프트) 주변 정규분포로 생성되고, 정상 밴드(중심선±3sigma)는 중심선을 따라
함께 이동합니다. 시나리오는 대상 설비(`--target`)에만 적용되고 나머지 설비는 normal로 생성됩니다.

수리한 설비는 시나리오와 무관하게 정상으로 강제됩니다(NEW_REPAIR01, [ADR-0007](adr/0007-equipment-repair.md)).
수리 API가 `equipment_masters.repaired_at`을 래치하면, 시뮬레이터는 매 tick 이 값을 읽어
힐 윈도우(`SIM_REPAIR_HEAL_MINUTES`, 기본 60분) 동안 정상값을 생성하고, 윈도우 경과 후 원래
시나리오를 재개합니다. 이로써 시연 중에는 재고장이 보이지 않고, 장시간 개발 실행에서는 최소 1시간
이후 재고장이 다시 나타납니다.

### 정상 프로파일

Etching 운영 프로파일(참고서 §2)은 다음과 같습니다. 압력 단위는 mTorr입니다.

| 변수 | 중심값 mu0 | sigma | LSL | USL | 권장 드리프트 |
| --- | --- | --- | --- | --- | --- |
| temperature | 60.00 | 0.10 | 58.50 | 61.50 | +0.03/tick |
| pressure | 42.00 | 0.67 | 30.00 | 55.00 | +0.40/tick |
| rf_power | 2.79 | 0.027 | 2.45 | 3.05 | -0.006/tick |
| gas_flow | 606.00 | 3.00 | 540.00 | 660.00 | -2.00/tick |

Deposition은 라인 구분용 데모 파생값이며 상세는 `profiles.py`를 참고하시기 바랍니다.

### 판정 규칙

- 급성(값이 동적 밴드 밖): ERR-401(온도)·ERR-301(압력)·ERR-201(rf)·WRN-501(가스)
- 냉각 복합 고장(온도 급성 상승 + 압력 급성 하강 동반): 대표 코드 ERR-402, `surface_codes`가 온도·압력 단일 코드(ERR-401·ERR-301)를 억제해 저널에 ERR-402 단건으로 표면화
- 드리프트/PM(밴드가 하드리밋 회랑 소진): WRN-701~704
- 변동성 증가(최근 창 1차 차분 표준편차가 정상의 2배 초과, 추세 무관): WRN-801
- 우선순위(참고서 §7)로 대표 알람 1개 선정, 밴드 이탈은 첫 tick 즉시 알람으로 저장해 최초 이상 접촉을 지연 없이 발령

다변량 관계 붕괴(전부 밴드 안이나 rf 상승·온도 하강)는 시뮬레이터가 생성하지 않고, 워처(watcher)가 별도로 감지해 WRN-901로 발령합니다.

### 시나리오 목록

| 시나리오 | 동작 | 기대 알람 |
| --- | --- | --- |
| normal | 4개 센서 정상 생성 | 없음 |
| cooling_fault_demo | 온도 급성 상승 + 압력 급성 하강 동반 | 복합 대표 ERR-402 (단일 ERR-401·ERR-301 억제) |
| temperature_drift_pm | 온도 중심선 상승 | WRN-701 |
| pressure_drift_pm | 압력 중심선 상승 | WRN-702 |
| rf_power_drift_pm | rf 중심선 하강 | WRN-703 |
| gas_flow_drift_pm | 가스 중심선 하강 | WRN-704 |
| mixed_pm_demo | 압력 상승 + rf 하강 | 먼저 버짓 소진된 WRN |
| variance_increase | 압력 변동성(sigma) 증폭 | WRN-801 |

RAG 데모에는 `pressure_drift_pm`·`gas_flow_drift_pm`을 우선 권장합니다(참고서 §8).

## 실행 방법

### CLI 직접 실행

```bash
uv run simulator                                                        # normal, 5초 주기, 무한
uv run simulator --scenario pressure_drift_pm --iterations 40 --drift-start 5 --target EQP-002
```

| 인자 | 기본값 | 설명 |
| --- | --- | --- |
| `--scenario` | normal | 위 시나리오 목록 중 하나 |
| `--interval` | 5.0 | 생성 주기(초) |
| `--iterations` | 무한 | 반복 횟수, 미지정 시 무한 |
| `--target` | EQP-003 | 시나리오 적용 대상 설비 |
| `--drift-start` | 10 | 드리프트 시작 tick |

드리프트/급성 시나리오는 `--iterations`로 유한 실행하는 것을 권장합니다. 골든 E2E 테스트도
이 유한 모드로 시나리오를 결정론적으로 주입합니다.

### docker-compose

`simulator` 서비스로 등록되어 있어 스택과 함께 자동 실행됩니다.

```bash
docker compose up -d          # db·api·mcp와 함께 시뮬레이터도 기동
```

시뮬레이터가 시드보다 먼저 기동되어도 종료되지 않고, `equipment_masters`가 채워질 때까지
대기한 뒤 적재를 시작합니다. 따라서 기동 순서와 무관하게 동작합니다.

## 동작 특성

- 한 주기(tick)마다 설비 수만큼 행을 적재합니다(설비 3대이면 tick당 3건).
- DB 연결·적재 실패 시 1회 재시도하고, 실패가 지속되면 해당 주기만 건너뛴 뒤 계속 진행합니다.
- 드리프트/변동성 시나리오는 `--drift-start` 이후 tick에 따라 중심선·변동성이 진행되어 알람 조건에 도달합니다.
- 대상 설비별 최근값 창을 유지해 변동성(WRN-801) 이동창 판정에 사용합니다.

## 데이터 규모 참고

기본값(5초 주기, 설비 3대) 기준 하루 약 5.2만 건(약 10 MB)이 적재됩니다. 현재 규모에서는
부하·용량 모두 무시할 수준이나, 장기간 상시 운영 시에는 `--interval` 조정 또는 오래된 로그
정리(retention)를 고려할 수 있습니다.
