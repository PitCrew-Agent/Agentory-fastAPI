# EXP-007 윈도우·stride 실시간성 재조정 + 지속 확인 규칙

## 목적·가설

확정 config(윈도우 120초·stride 60초)는 EXP-003에서 v1 기준 오탐 최소만 보고 고른
값이라 실시간 반응이 느립니다. 윈도우와 stride를 독립 스윕해 실시간성을 지배하는 축을
규명하고, stride 단축에 따른 오탐 증가를 지속 K윈도우 확인 규칙으로 억제할 수 있는지
검증합니다.

## 설정

- 스윕: 윈도우 [30, 60, 120, 240]초 x stride [5, 15, 30, 60]초, raw PCAX 경로, v2
- 지속 규칙: scoring.sustained(연속 K윈도우 초과 시 발령), confirm_k config
- 실시간 config: 윈도우 60초·stride 30초·EWMA·K=2 (exp_007_realtime), K=1 대조군 병행
- config: exp_007_sweep / exp_007_realtime / exp_007_realtime_nok

## 발견 1: 실시간성은 stride가 지배, 윈도우는 무관

급성 감지 지연은 오직 stride를 따라가고 윈도우 크기와 무관합니다.

| stride | 급성 지연 | 윈도우 30~240초 전체에서 |
| --- | --- | --- |
| 5초 | 0초 | 전부 0초 |
| 15초 | 10초 | 전부 10초 |
| 30초 | 25초 | 전부 25초 |
| 60초 | 55초 | 전부 55초 |

지연 ≈ stride입니다. 판정 기회 사이 간격이 곧 반응 지연이기 때문입니다. EXP-003에서
"지연은 튜닝 무관"이라 결론냈던 것은 v1 한정이었습니다(정정, 아래 발견 4).

## 발견 2: 윈도우는 진동 감지 품질을 지배

진동(oscillation)은 큰 윈도우가 주기를 평균내 감지가 늦습니다.

| 윈도우 | 진동 감지 지연 (stride 30초 기준) |
| --- | --- |
| 30초 | 160초 |
| 60초 | 70초 (최적) |
| 120초 | 85초 |
| 240초 | 175초 |

윈도우 60초가 진동 감지 최적입니다. 너무 짧으면 상관 피처 표본이 부족하고, 너무 길면
주기가 평균됩니다.

## 발견 3: 오탐-반응 상충과 지속 규칙의 한계

stride를 당기면 반응이 빨라지지만 오탐이 늘고, 지속 K규칙은 이를 부분적으로만
상쇄합니다 (윈도우 60초, raw 경로).

| 설정 | 급성 지연 | 오탐/설비·일 | recall |
| --- | --- | --- | --- |
| stride 60초 (기존) | 55초 | 4.9 | - |
| stride 15초, K=1 | 10초 | 15.4 | 0.86 |
| stride 15초, K=2 | 25초 | 11.7 | 0.82 |
| stride 15초, K=3 | 40초 | 11.3 | 0.77 |

K규칙은 오탐을 15.4 → 11.7로 줄이지만(-24%), 급성 지연을 늘리고 recall도 떨어뜨립니다.
EWMA 경로에서는 효과가 더 작습니다(18.8 → 17.5). 이유는 잔여 오탐이 고립 스파이크가
아니라 **점화 모드 전이**(지속형)이기 때문입니다. K규칙은 고립 스파이크만 억제하므로,
지속형 오탐은 통과합니다. 앞선 EXP-006의 "K규칙으로 상쇄" 기대를 데이터가 부분
정정합니다: K는 완만한 레버이며, 지배적 오탐원인 모드 전이는 레시피 컨텍스트 마스킹으로
풀어야 합니다.

## 발견 4: 급성 속도는 이 레이어의 부담이 아님

레이어드 구조에서 급성·안전은 결정론 규칙 레이어가 포인트 단위로 즉시 잡습니다. 따라서
이상 레이어가 급성 속도(stride 단축)를 쫓을 이유가 약하고, 이상 레이어의 실익은
드리프트·진동·상관 붕괴 반응입니다. 이 관점에서 stride는 "급성 10초"가 아니라 "드리프트
55→40초, 진동 175→70초, 상관 붕괴 595→460초" 개선으로 평가해야 합니다.

## 결론: 서빙 파라미터 재확정

| 파라미터 | 기존 (EXP-003) | 재확정 (EXP-007) | 근거 |
| --- | --- | --- | --- |
| 윈도우 | 120초 | **60초** | 진동 감지 최적 (발견 2) |
| stride | 60초 | **30초** | 드리프트·상관 반응 개선, 오탐 상충 균형 (발견 1·3) |
| 지속 K | 없음 | **K=2** | 완만한 오탐 억제, 반응 손실 최소 (발견 3) |
| 규칙 레이어 | 유지 | 유지 | 급성 즉시 감지 담당 (발견 4) |

재확정 config(60초/30초/K2) 실측: 상관 붕괴 감지 520초(기존 595초), 진동 130초, 드리프트
81초, 오탐 17.5/설비·일, recall 0.91. 급성은 규칙 레이어가 계속 즉시 담당합니다.

## 한계와 후속

- 지배적 오탐원(점화 모드 전이)은 튜닝으로 못 풀며 레시피 상태 신호 마스킹이 정석,
  서빙 구현의 별도 과제
- 오탐 절대 수준(17.5/일)은 30분 dedup 버킷 통과 후 실제 알림 수로 재평가 필요
- 서빙 실행 주기 = stride(30초 배치)로 직결, 스코어링 부하는 실측 필요
- K·stride 최종값은 섀도우 모드에서 운영자 피드백으로 재조정하는 것을 권장
