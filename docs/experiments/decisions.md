# 이상 감지 설계 결정 기록

실험 진행 중 내린 설계 결정과 그 근거를 누적 기록합니다. 각 결정은 대안과의 정량 비교와
선택 근거를 남기며, 이후 실험 결과로 뒤집히면 상태를 갱신하고 뒤집은 실험 ID를 명시합니다.
시행착오·중간 발견은 문서 하단 로그에 날짜와 함께 추가합니다.

상태 표기: 채택 / 검증 대기 (실험으로 확인 예정) / 기각

## D1. 감지 구조: 레이어드 유지 (채택)

기존 고정 임계·알람 코드를 제거하고 SSL 점수로 대체할지, 유지한 채 보완 레이어로
추가할지에 대한 결정입니다.

| 비교 항목 | 선택안: 레이어드 (임계 유지 + SSL 추가) | 대안: 임계 제거 후 SSL 단독 |
| --- | --- | --- |
| 안전 임계 감사 가능성 | 결정론 규칙으로 완전 보장 | 학습 모델 의존, 감사 불가 |
| 급성 이상 감지 지연 | 포인트 단위 즉시 | 윈도우 길이만큼 지연 |
| 임계 안쪽 복합 이상 | SSL 레이어가 커버 | 동일하게 커버 |
| 장애 시 폴백 | 규칙 레이어 단독으로 동작 지속 | 폴백 없음 |

선택 근거: 과온·과압 등 안전 한계는 결정론적이고 감사 가능해야 하며, SSL은 임계가 못
잡는 "임계 안쪽 패턴 이탈"을 보완하는 역할로 추가합니다. LLM은 판정에서 설명 역할로
전환하며, 판정 대체 대상은 임계가 아니라 LLM입니다.

## D2. v0 방법: PCA MSPC 선행, 임베딩 거리는 v1 (채택)

최초 구상(임베딩 + cosine similarity)으로 직행할지, 재구성 기반으로 시작할지에 대한
결정입니다.

| 비교 항목 | 선택안: PCA MSPC (T²+SPE) | 대안 1: 임베딩 거리 직행 | 대안 2: 딥 AE 재구성 |
| --- | --- | --- | --- |
| 채널별 기여도 (LLM 설명 근거) | 수식으로 직접 산출 | 별도 기법 필요 | 채널별 오차로 산출 |
| 학습 비용 | 초 단위 (sklearn) | encoder 학습 필요 | GPU 학습 필요 |
| 구현 공수 | 1주 내 | 3주+ | 2주+ |
| 복합 이상 (상관 붕괴) | SPE가 직접 포착 | encoder 품질 의존 | 포착 가능 |
| 검증 이력 | 화학공정 수십 년 SPC 계보 | 논문 위주 | 사례 다수 |

선택 근거: 평가 체계가 없는 상태에서 encoder부터 넣으면 개선 여부를 판정할 수 없습니다.
v0로 파이프라인 전체와 베이스라인 수치를 먼저 확보한 뒤, v1(TS2Vec)을 동일 지표로 A/B
비교합니다. encoder 교체 seam은 `anomaly.models.base.AnomalyDetector`로 확보했습니다.

## D3. baseline 표현: 임베딩 은행 + kNN 거리 (검증 대기, EXP-005)

정상 기준을 단일 벡터로 둘지, 정상 임베딩 집합으로 둘지에 대한 결정입니다.

| 비교 항목 | 선택안: 임베딩 은행 + kNN | 대안 1: 단일 벡터 + cosine | 대안 2: Mahalanobis |
| --- | --- | --- | --- |
| 다중 운전 모드 (기동·부하변동·idle) | 모드별 이웃으로 대응 | 모드 전환을 오탐 처리 | 단봉 가정, 다중 모드 취약 |
| 크기 정보 보존 | 거리라서 보존 | 방향만 비교, 크기 소실 | 보존 |
| 스코어링 비용 | 은행 크기 비례 (수만 건이면 ms 단위) | 최소 | 공분산 역행렬 1회 |

선택 근거: 정상 운전은 다중 모드라서 단일 벡터 cosine은 "정상인데 모드가 다른 구간"을
오탐합니다. EXP-005에서 cosine 단일 baseline을 대조군으로 함께 측정해 정량 확인 예정입니다.

## D4. 코드 위치: 같은 레포 별도 패키지 (채택)

| 비교 항목 | 선택안: src/anomaly 패키지 | 대안: 별도 레포 |
| --- | --- | --- |
| 도메인 모델 공유 | simulator·스키마 직접 import | 중복 정의 또는 패키지 배포 |
| CI·컨벤션 재사용 | ruff·pytest 그대로 | 파이프라인 복제 |
| API 이미지 오염 | dependency-group 격리로 차단 | 완전 격리 |
| 배포 단위 | 별도 ECS 서비스로 분리 가능 | 동일 |

선택 근거: E0가 simulator 순수 함수를 직접 재사용한 것 자체가 같은 레포의 이득을
입증합니다. 학습 코드가 커지는 시점의 절단선은 레포 분리가 아니라 학습/서빙 분리입니다.

## D5. 아티팩트 배포: 코드만 이미지, 가중치 S3, baseline RDS (채택)

| 아티팩트 | 갱신 주기 | 배포 위치 | 이미지에 굽지 않는 이유 |
| --- | --- | --- | --- |
| 스코어링 코드 | 릴리스마다 | 컨테이너 이미지 | 해당 없음 (이미지가 맞음) |
| encoder 가중치 | 재학습 시 | S3 버전 경로 + env 핀 | 재학습 주기 ≠ 릴리스 주기 |
| 설비별 baseline·임계 | 수시 (drift 갱신) | RDS | 갱신마다 재배포 불가 |

선택 근거: baseline은 정비 이벤트·드리프트 정책에 따라 런타임에 갱신되는 데이터이므로
이미지에 넣으면 갱신 정책 자체가 무너집니다. 가중치는 env 핀 방식이라 A/B 시 같은
이미지로 URI만 바꿔 두 태스크를 띄울 수 있습니다.

| 비교 항목 | 선택안: MLflow 로컬 | 대안 1: 마크다운+JSON | 대안 2: W&B |

지표는 MLflow에 자동 기록하고 해석·결론은 EXP-NNN 문서에 수동 기록하는 이원화입니다.

## D7. 평가 세트 관리: git 커밋으로 얼리기 (채택)

| 비교 항목 | 선택안: 커밋 얼리기 | 대안: seed 재생성 |
| --- | --- | --- |
| 재현 보장 | 바이트 단위 불변 | Python·라이브러리 버전에 종속 |
| 저장 비용 | 약 1MB (parquet) | 0 |
| 팀 공유 | clone 즉시 사용 | 생성 스크립트 실행 필요 |

선택 근거: 용량이 작아 커밋 비용이 무시 가능한 반면, seed 재생성은 런타임 버전 변화로
세트가 미세하게 달라질 위험이 있어 실험 간 비교 전제가 흔들립니다. 추가 안전장치로
생성은 설비별 독립 rng라서 세그먼트를 추가해도 기존 값이 변하지 않습니다.

## D8. v1 encoder: TS2Vec (보류, EXP-005 결과)

EXP-005에서 압축 구현 기준 v0 초과 근거가 없어 채택을 보류합니다. 판정 기준이었던
corr_break에서 표현에 신호 자체가 없었고(이상 전후 점수 중앙값 동일), 오탐 소폭
우위·지연 소폭 열위로 교체 비용을 정당화하지 못합니다. corr_break의 우선 경로는
점수 누적(EXP-006)으로 이동하며, 긴 문맥 encoder 재도전은 실측 데이터 이후 판단합니다.

| 비교 항목 | 선택안: TS2Vec | 대안 1: Anomaly Transformer 류 | 대안 2: PatchTST 마스킹 |
| --- | --- | --- | --- |
| 학습 자원 | CPU/MPS 가능 | GPU 권장 | GPU 권장 |
| 재현성 평판 | 공개 구현 안정 | 벤치마크 재현 논란 다수 | 양호 |
| 운영 복잡도 | encoder 단독, 거리 계산 분리 | 판정 로직 내장, 결합도 높음 | 중간 |

선택 근거: 이상 판정을 모델에 내장하지 않고 encoder(표현)와 거리(판정)를 분리해야
D3의 baseline 교체·drift 갱신 정책과 직교로 조합할 수 있습니다.
