# 이상 감지 스코어러 서빙

실험(EXP-000~007)으로 확정한 이상 감지 아키텍처를 watcher 모듈에 통합한 서빙 구성입니다.
규칙 임계가 못 잡는 임계 안쪽 이상(센서 간 상관 붕괴·완만 드리프트)을 주기적으로 감지해
기존 알람·알림 파이프라인으로 발령합니다.

## 구성 요소

| 요소 | 위치 | 역할 |
| --- | --- | --- |
| 스코어러 | `watcher/detector.py` | PCAX + EWMA 경로 판정 (순수 로직) |
| 모델 저장 | `equipment_anomaly_models` 테이블 | 공정 유형별 PCAX 파라미터 (JSON) |
| 학습 CLI | `anomaly-fit` | 정상 telemetry로 적합·저장 |
| 데이터 접근 | `watcher/anomaly_repository.py` | 모델 적재·시계열 조회·알람 전이 |
| 주기 워처 | `watcher/anomaly_worker.py` | 주기(=stride) 스코어링·발령 |

## 동작 흐름

```
[anomaly-worker, 30초 주기]
   → 설비별 최근 300행 조회 → 스코어러 판정 (윈도우 60초·stride 30초·EWMA·K2)
   → 발령 시 EquipmentAlarm(WRN-901, metric=최대기여 채널) 기록
   → (기존) sync_from_alarms → 30분 dedup → notifications → SSE
```

발령 코드는 `WRN-901`(통계 이상, 심각도 주의)이며 규칙 코드(ERR/WRN-50x~80x)와 구분됩니다.
`metric`에는 T²/SPE 최대 기여 센서가 기록되어 알림·대응 계획의 설명 근거가 됩니다.

점화·램프업 같은 모드 전이는 raw 점수가 급등(수천대)하는데, 진짜 이상(수 이하)과 완전
분리되므로 `anomaly_transition_threshold`(기본 1000) 이상 구간과 이후 정착 구간을 발령에서
제외합니다(EXP-008). 급성은 규칙 레이어가 담당하므로 이상 레이어의 전이 무시는 안전하며,
평가셋 v2에서 모드 전이 오탐을 recall 손실 없이 79% 감축했습니다. 실측 램프는 raw 점수가
낮을 수 있어 섀도우 모드에서 임계 재조정을 권장합니다.

## 섀도우 모드 (BE_ANOM01_SHADOW01)

실발령 전 검증 단계입니다. `ANOMALY_SHADOW_MODE=true`(기본)면 스코어러가 실데이터에
동작하되 WRN-901을 알림 파이프라인에 쏘지 않고 `equipment_anomaly_shadow_events`
관찰 저널에만 기록합니다. 운영자 노출 없이 규칙 레이어와 비교 관찰할 수 있습니다.

```bash
uv run anomaly-shadow-report --days 7   # 섀도우 vs 규칙 비교
```

리포트는 감지를 세 가지로 분류합니다.

| 분류 | 의미 |
| --- | --- |
| detector-only | 섀도우만 발생, 규칙이 놓친 임계 안쪽 이상 후보 |
| overlapping | 섀도우·규칙 시간 겹침, 동일 이상 양쪽 감지 |
| rule-only | 규칙만 발생, 섀도우 미감지 (급성 등, 규칙 레이어 담당) |

detector-only가 실제 이상인지 오탐인지 운영자가 리뷰해 실발령 전환·파라미터 조정을
결정합니다. 이 라벨이 이후 레시피 마스킹·설비별 캘리브레이션·반지도 전환의 근거입니다.

## 배포 절차

```bash
uv run alembic upgrade head          # 이상 감지 테이블 생성
uv run anomaly-fit                   # 공정 유형별 모델 적합·저장 (정상 데이터 필요)
# 1단계 섀도우: ANOMALY_DETECTION_ENABLED=true, ANOMALY_SHADOW_MODE=true 후 재기동
#   → N주 관찰, anomaly-shadow-report로 규칙 비교
# 2단계 실발령: 검증 후 ANOMALY_SHADOW_MODE=false 후 재기동 → WRN-901 실발령
```

모델 미적재 상태에서는 워처가 즉시 반환하므로 활성화해도 무해합니다. 서빙 파라미터는
`core/config.py`의 `anomaly_*` 필드로 조정하며 기본값은 EXP-006·007 확정값입니다.

## baseline drift 자동 갱신 (BE_ANOM01_DRIFT01)

설비 마모로 정상이 서서히 이동하고 정비 후 리셋되므로, 고정 모델은 시간이 지나며 오탐이
늘어납니다. `ANOMALY_REFIT_ENABLED=true`면 재적합 워처가 `ANOMALY_REFIT_INTERVAL_HOURS`
마다 staleness(`ANOMALY_REFIT_STALE_HOURS`) 초과 모델을 최근 정상 데이터로 재적합해
baseline이 현재 정상을 추종합니다.

boiling-frog(서서히 진행되는 고장을 정상으로 학습) 방지 장치는 세 가지입니다.

| 장치 | 효과 |
| --- | --- |
| 정상 한정 (alarm_code IS NULL) | 알람 구간 제외 |
| 최근성 경계 (recency_days) | 오래된 정상 age-out |
| 정비 인지 (repaired_at 이전 제외) | 정비 전 열화 정상으로 정비 후 모델 오염 방지 |
| 표본 가드 (MIN_TRAIN_WINDOWS) | 데이터 부족 시 기존 모델 유지 |

`anomaly-fit` 수동 재실행으로도 즉시 갱신할 수 있습니다.

## 설비별 임계 캘리브레이션 (BE_ANOM01_CALIB01)

모델은 공정 유형 단위로 적합되어 동일 공정 내 설비 개체 차(챔버 차·센서 오프셋)를 반영하지
못합니다. 공유 모델은 유지한 채 각 설비의 EWMA 한계만 그 설비 자신의 정상 분포로
캘리브레이션해 개체 오프셋을 흡수합니다. `anomaly-fit` 실행 시 함께 산출되며
`equipment_anomaly_calibrations`에 저장됩니다.

| 장치 | 효과 |
| --- | --- |
| 표본 가드 (MIN_CALIBRATION_WINDOWS) | 표본 부족 설비는 미저장, 공정 한계로 폴백 |
| 비율 클램프 (min/max_ratio) | 추정 잡음으로 인한 과민·과둔감 차단 |
| EWMA 워밍업 제외 | 초기 전이가 극단 분위수를 부풀리는 것 차단 |

### 한계 캘리브레이션 오염 수정

캘리브 도입 과정에서 기존 한계 산출의 오염 두 가지를 발견해 함께 수정했습니다.

| 오염 | 증상 | 수정 |
| --- | --- | --- |
| EWMA 워밍업 | 첫 윈도우 점수가 높은 설비는 감쇠 구간이 상위 표본을 독점, 한계 최대 4.4배 팽창 | 워밍업(시정수 5배) 제외 후 분위수 |
| 설비 경계 전이 | 이어붙인 시퀀스에 EWMA를 통째로 돌려 경계마다 전이 발생, 공정 한계 34% 팽창 | 파트별 EWMA 후 결합 (실험 하네스와 동일) |

수정 결과 공정 한계는 0.728에서 0.544로 낮아졌고(의도한 q0.999 민감도 회복), 설비별
한계는 공정 대비 0.94~1.07배로 수렴했습니다. 동일 프로파일 설비에서는 이 수렴이 정상이며,
실측 데이터에서 개체 차가 있으면 그만큼 벌어집니다. 한계가 낮아진 만큼 알람이 늘 수 있어
섀도우 모드에서 먼저 관찰하는 것을 권장합니다.

## 아키텍처 정합

- 모델 파라미터는 RDS에 저장(확정 아키텍처), pickle 대신 JSON 배열 직렬화로 버전 견고
- baseline·임계가 RDS에 있어 재적합만으로 drift 갱신 가능 (워처 자동 또는 CLI 수동)
- 규칙 레이어는 유지되며 본 스코어러는 보완 레이어 (급성은 규칙이 즉시 담당)

## 남은 과제 (후속)

본 문서 최초 작성 시점의 후속 과제 네 건은 모두 구현되었습니다. 결정 배경과 실측 근거는
[ADR-0010](adr/0010-anomaly-detection.md)에 정리되어 있습니다.

| 최초 과제 | 상태 |
| --- | --- |
| 레시피 컨텍스트 마스킹 | 레시피 신호 없이 raw 점수 기반 전이 억제로 구현 (EXP-008, 오탐 -78.8%) |
| 설비별 캘리브레이션 | 구현 (BE_ANOM01_CALIB01), 실측 데이터에서 개체 차 재확인 필요 |
| baseline drift 자동 갱신 | 구현 (BE_ANOM01_DRIFT01), 기본 비활성 |
| 섀도우 모드 | 구현 (BE_ANOM01_SHADOW01), 관찰 진행 단계 |

현재 남은 과제는 다음과 같습니다.

- 실발령 전환: 섀도우 리포트의 detector-only 라벨을 운영자가 리뷰한 뒤 결정합니다
- 임계 안쪽 완만 드리프트(drift_inband): 규칙·통계 두 레이어 모두 감지하지 못하는 사각이며
  장기 추세 전용 경로 등 별도 레버가 필요합니다
- 실측 기반 파라미터 재조정: 전이 임계·캘리브 클램프·EWMA 한계는 모두 합성 데이터 기준값입니다
- v1(TS2Vec) 재검토: 실측 데이터 확보 이후 판단합니다
- 재적합 boiling-frog 방지 장치의 실측 검증
